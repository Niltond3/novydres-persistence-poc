# 6. RESPONSABILIDADE DOS ARQUIVOS

## `.AGENT.md`

Define **como um agente deve trabalhar naquele escopo**.

Não deve funcionar como enciclopédia.

Deve conter apenas:

```text
# Mission
# Scope
# Authority
# Required Reading
# Invariants
# Allowed Changes
# Forbidden Changes
# Dependencies
# Update Contract
# Definition of Done
```

O `.AGENT.md` deve responder:

> "Quais regras eu preciso obedecer para trabalhar neste capítulo sem quebrar Novydres?"

Não copie o conteúdo inteiro do `CANON.md`.

---

## `.CONTEXTG.md`

É o **context gateway** daquele escopo.

Sua função é permitir que um novo agente compreenda rapidamente onde está entrando.

Estrutura preferida:

```text
# Purpose
# Current State
# Canonical Anchors
# Hard Constraints
# Dependencies
# Active Work
# Open Issues
# Restart Point
# Last Updated
```

Ele deve ser **curto e operacional**.

Não é:
- arquivo de lore;
- histórico completo;
- dump do Handoff;
- changelog;
- substituto de CANON.md.

Meta:

- normalmente 40–100 linhas;
- evitar passar de aproximadamente 150 linhas;
- remover prosa ornamental;
- preferir referências aos arquivos corretos.

O agente deve conseguir ler `.CONTEXTG.md` e saber **onde procurar**, não necessariamente aprender todo o capítulo ali.

---

## `CANON.md`

Contém apenas material efetivamente vigente.

Não misturar:
- proposta;
- brainstorming;
- hipótese;
- pendência;
- conteúdo rejeitado.

Antes de considerar o bootstrap concluído, simule esta situação:

> "Um novo agente entra no projeto sem ler o MASTER HANDOFF V1 e recebe uma tarefa exclusivamente sobre POIs."

Ele deve conseguir:

1. ler `.CONTEXTG.md` raiz;
2. identificar `11_POI_REGISTRY`;
3. ler `11_POI_REGISTRY/.AGENT.md`;
4. ler `11_POI_REGISTRY/.CONTEXTG.md`;
5. localizar apenas os documentos necessários;
6. compreender estados e restrições;
7. executar o trabalho sem carregar o projeto inteiro;
8. não contradizer regras de cartografia ou linguagem visual porque as dependências estão explicitamente indicadas.

- Master Map;
- Cartografia;
- GIMP/pipeline.
